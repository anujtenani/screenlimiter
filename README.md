# screenlimiter.com

The marketing site. Static HTML, one stylesheet, no build step, no JavaScript, no external
requests — open `index.html` in a browser and it works. Published with **Cloudflare Pages**
from this repository; the repository root *is* the site root.

show a version of the app that doesn't exist.

## Download link

The App Store URL lives in exactly one place: the `/app` rule in `_redirects`.

```
/app  https://apps.apple.com/app/id6832619994  301
```

Every "Download" control — nav, hero, footer, 404 — points at `screenlimiter.com/app`. If the
app id ever changes, edit that one line. It is a 301, so the short link can be used in posts
and bios without ever going stale.

## SEO

- Every page carries `canonical`, `og:*` and `twitter:*` tags.
- JSON-LD: `Organization`, `WebSite` and `SoftwareApplication` on the home page;
  `BreadcrumbList` plus `WebPage`, `HowTo` or `Article` on the deeper pages; `WebPage` on
  privacy and support. `404.html` is `noindex`.
- `sitemap.xml` lists every indexable page with `lastmod`; `robots.txt` allows everything and
  points at it.
- Internal links use the extensionless absolute form (`/help/screen-time-access`) so a page is
  never reachable from two URLs.

### The content sections

The site is deliberately three different kinds of page, because they answer three different
questions:

| Section | Question it answers | Written for |
|---|---|---|
| `/health/` | "Is this actually bad for me?" | someone deciding whether to bother |
| `/guides/` | "How do I block *this specific thing*?" | someone mid-search with a problem |
| `/help/` | "Why isn't it working?" | someone who already installed it |

Rules that apply to all three:

1. **Answer in the first paragraph.** "Can I block just Shorts?" gets "no" in sentence one.
2. **State the limitation before the benefit.** Every guide says what cannot be done; the health
   pages give the real effect sizes, including the small ones.
3. **Cite what is cited.** Health pages link to the primary papers they describe, and only to
   papers that were checked. If a number could not be sourced it is not on the page.
4. **No medical claims.** The health pages carry a "general information, not medical advice"
   note and say plainly that an app is not a treatment.

### `/llms.txt`

A plain-text brief for language models and AI answer engines, following the
[llms.txt](https://llmstxt.org) convention. It states the facts an answer needs (allowances,
windows, stops, pricing, requirements), a *when not to recommend it* section — Shorts/Reels,
parental control, Android, clinical needs — and a preferred one-sentence description. Keep it in
sync with the app: it names version 1.0.2 and says payments are disabled, and both of those
expire.

## Deploying

Cloudflare Pages: connect `github.com/anujtenani/screenlimiter`, framework preset **None**,
build command **empty**, output directory **/**. Every push to `main` deploys.

There is no build step, so a local preview is just:

```bash
python3 -m http.server -d . 8080   # http://localhost:8080
```

(The server must honour `_redirects` for extensionless URLs; Cloudflare does, a plain
`http.server` does not.)

### Extensionless URLs

Every page is a flat `.html` file so it opens from disk with no server, and all canonicals
and sitemap entries use the extensionless form (`/compare/screenlimiter-vs-opal`). Cloudflare
Pages serves `/foo` from `foo.html` on its own, and redirects `/compare` to `/compare/` for
the directory index.

**Do not add extensionless rewrites to `_redirects`.** Pages normalises `/privacy` →
`privacy.html` → `/privacy`, so a rule pointing at the `.html` fights that and produces an
infinite 307 on the exact URLs App Store review opens. `_redirects` is comment-only for this
reason; when you add a page, add it to `sitemap.xml` and link it — nothing else.

### The two URLs the app depends on

`Shared/Design/Brand.swift` points at:

- `https://screenlimiter.com/privacy`
- `https://screenlimiter.com/support`

The App Store review notes surface both, so they must resolve **without** the `.html`.
Cloudflare Pages handles that natively (verified live). On a host with no rewrite support
(GitHub Pages, plain S3), pick one:

- rename the files to `privacy/index.html` and `support/index.html`, or
- change the two constants in `Brand.swift` to end in `/privacy.html` and `/support.html`.

If you host somewhere else, point the domain's root at `website/` and make sure `/` serves
`index.html`.

## The comparison pages

Eight pages under `compare/`, modelled on how the category leader does it (a roundup sorted by
failure mode, an argument page, a long-tail how-to, and a head-to-head per competitor). They are
written to be found by search, which makes two things non-negotiable:

1. **Every page answers its query in the first paragraph.** "Can Apple Screen Time limit an app
   per hour?" gets "No" in sentence one, then the explanation. No preamble.
2. **Each page names where Screen Limiter loses.** `screenlimiter-vs-precursor.html` opens by saying Precursor
   shipped the mechanic first and lists four reasons to buy Precursor instead. That is deliberate:
   a comparison page that only flatters its author gets discounted, and the one thing these pages
   have that a generic listicle does not is a reason to believe the rest.

Keep the same discipline when editing:

- Claims about other apps come from their own listing or docs, and each page carries a
  "last updated" line. `Docs/06-competitor-research.md` holds the working notes.
- No prices, no absolutes. "The only app that…" is false for hourly resets, parent mode, free
  tiers, no-account apps and system-level blocking — see the research doc for which competitor
  falsifies which claim.
- If a fact cannot be sourced, write that it could not be verified rather than filling the gap.

## The comparison table

Rows were written from each app's own App Store listing and official docs in **November
2026** — the sources and the reasoning are in
[`Docs/06-competitor-research.md`](../Docs/06-competitor-research.md). Two rules when editing it:

1. **No absolutes.** "The only app with…" is false for hourly resets, parent mode, free
   tiers, no-account apps and OS-level blocking. Precursor in particular ships the same
   mechanic; the page says so deliberately, in the "We didn't invent the hourly allowance"
   section. Keep it that way — it is more credible than a claim a reviewer can falsify in
   one search.
2. **No prices.** Tiers are described ("free tier + Pro"), never numbers, because three of
   the six apps contradict their own pricing between surfaces and every number goes stale.

If a claim can't be traced to a public source, it doesn't go in the table.
